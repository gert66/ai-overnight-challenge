2. Maak op je eigen computer een SSH-key

SSH is de veilige verbinding tussen jouw laptop en de Linux-VM.

Windows PowerShell

ssh-keygen -t ed25519 -C "jouw-email@example.com"

Druk op Enter voor de standaardlocatie. De publieke sleutel staat meestal in C:/Users/JOUW_NAAM/.ssh/id_ed25519.pub.

type $env:USERPROFILE/.ssh/id_ed25519.pub

macOS / Linux

ssh-keygen -t ed25519 -C "jouw-email@example.com"
cat ~/.ssh/id_ed25519.pub
Kopieer alleen de publieke sleutel, het bestand met .pub. Deel nooit je privésleutel.

4. Maak de eerste SSH-verbinding

Hetzner toont een publiek IP-adres. Vervang SERVER_IP hieronder door jouw echte IP.

ssh root@SERVER_IP

De eerste keer vraagt SSH of je de fingerprint vertrouwt. Controleer dat je met het juiste IP verbindt en antwoord daarna yes.

Maak meteen een gewone beheerder

adduser aiadmin
usermod -aG sudo aiadmin
mkdir -p /home/aiadmin/.ssh
cp /root/.ssh/authorized_keys /home/aiadmin/.ssh/authorized_keys
chown -R aiadmin:aiadmin /home/aiadmin/.ssh
chmod 700 /home/aiadmin/.ssh
chmod 600 /home/aiadmin/.ssh/authorized_keys

Test daarna in een nieuwe terminal:

ssh aiadmin@SERVER_IP

7A. Optioneel maar erg nuttig: Desktop Commander

Desktop Commander is de gereedschapsbrug tussen ChatGPT en je VM. De orchestrator bestuurt autonome jobs. Desktop Commander staat daar los van en kan op jouw verzoek rechtstreeks de machine inspecteren en bedienen: bestanden lezen en wijzigen, directories bekijken, processen starten, logs volgen en terminalcommando's uitvoeren.

Installeren en koppelen

Node 18 of nieuwer is vereist. Start op de VM de Remote Device:

npx @wonderwhy-er/desktop-commander@latest remote

De eerste keer verschijnt een eenmalige verificatiecode. Bevestig die in de browser. Voeg daarna in ChatGPT of een andere MCP-client de Remote MCP-server toe:

https://mcp.desktopcommander.app/mcp

Na OAuth-autorisatie kan de chat de gekoppelde VM bereiken zolang de Remote Device draait. In onze challenge-VM draait Desktop Commander Remote als blijvende service, zodat de verbinding niet afhankelijk is van een open SSH-terminal.

Waarom dit zo handig is

Je hoeft daardoor veel minder handmatig via SSH te kopiëren en plakken. ChatGPT kan bijvoorbeeld controleren of een service draait, een configuratiebestand aanpassen, een log uitlezen of een Git-status bekijken terwijl jij in hetzelfde gesprek blijft.

Belangrijk: Desktop Commander heeft uitvoeringsrechten op de machine binnen de ingestelde toegangsgrenzen. Behandel het daarom als beheerderstoegang: beperk toegestane directories en commando's, bewaar secrets buiten Git en koppel alleen machines die je daarvoor bewust hebt ingericht. Controleer pairing-codes voordat je een nieuw device autoriseert.

8. Environment variables en secrets veilig instellen

Zet tokens en API-keys nooit rechtstreeks in code of Git.

Project-specifiek .env-bestand

cd ~/projects/my-ai-builds
nano .env

Voorbeeld:

APP_ENV=development
MY_SERVICE_TOKEN=plak_hier_een_echte_token

Zet het bestand buiten Git:

printf "
.env
.env.*
" >> .gitignore
chmod 600 .env

Niet-geheime shell-instellingen

nano ~/.bashrc
# voorbeeld:
export AI_PROJECT_ROOT="$HOME/projects"
source ~/.bashrc
Voor echte productie-secrets gebruik je liever een secrets manager. Voor een eerste privé-experiment is een niet-gecommit bestand met strikte permissies een begrijpelijke start.

9. Doe eerst één handmatige end-to-end test

cd ~/projects/my-ai-builds
mkdir hello-agent && cd hello-agent
npm init -y
printf 'console.log("AI build environment works")
' > index.js
node index.js

Laat daarna de coding agent één test toevoegen. Controleer het resultaat en push een aparte branch:

git checkout -b experiment/first-agent-test
git add .
git commit -m "First agent environment test"
git push -u origin experiment/first-agent-test
Pas als VM → agent → test → Git commit → GitHub push werkt, voeg je de orchestrator toe.

10. Voeg daarna de orchestrator toe

Versie 1 hoeft maar zes dingen te kunnen:

FaseFunctie
PLANMaak één concrete bouwstap met acceptance criteria.
BUILDStart de coding agent in de juiste repository.
TESTDraai vaste testcommands.
REVIEWLaat een aparte review-run controleren.
COMMITCommit alleen als bewijs en review groen zijn.
REPEATHerhaal tot de acceptance criteria zijn gehaald.

Bewaar state buiten het model, bijvoorbeeld in state.json, zodat een restart kan hervatten.

11. Voeg monitoring en watchdog toe

Laat actieve jobs periodiek een heartbeat schrijven. Een aparte watchdog kijkt of die heartbeat nog recent is en onderneemt alleen actie als een job aantoonbaar stilvalt.

{
  "job_id": "demo-001",
  "phase": "WORKING",
  "heartbeat": "2026-09-17T08:30:00Z"
}

Gebruik op Linux bijvoorbeeld systemd voor de orchestrator en een timer of cron voor periodieke controles. Geef retries altijd een maximum.
