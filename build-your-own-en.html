What do I need, what does it cost, and how do I build my own AI software factory?

You do not need to start with a large cluster. This challenge ran on a small VM with 2 vCPU and 3.7 GiB RAM. The core is a Linux machine, Git, an agent that can write code, an orchestrator that monitors the process, and tests that determine when something is actually finished.

Start deliberately small

1. One VM

Use a small Ubuntu server. For this challenge, 2 vCPU and about 4 GB RAM were enough.

2. One repository

Run your first autonomous workflow on one GitHub repository, with branches and clear commits.

3. One AI environment

Start with either ChatGPT or Claude. Add multiple models and automatic routing later, once the basic setup is stable.

4. Expand only after that

Add reviews, retries, watchdogs, multiple providers, and a dashboard once the simple chain works reliably.

Build from scratch

1. VMUbuntu/Linux
2. Gitrepo + branches
3. AIChatGPT or Claude
4. Orchestratorstate machine
5. Testsacceptance gates
6. Monitorwatchdog + dashboard

Step 1. Use a small VM

Start with about 2 vCPU, 4 GB RAM, and 40 GB disk. Install Python, Node/npm, and Git. Add capacity only when you measure real bottlenecks.

Step 2. Make Git authoritative

Each job works on its own branch. Have the orchestrator verify that the tree is clean, the branch is current, and approved batches are committed separately.

Step 3. Choose one AI environment

Start with ChatGPT or Claude and keep the first workflow simple. Once that runs reliably, you can add separate coding agents, multiple providers, and automatic model routing.

Step 4. Build a real state machine

Use explicit phases such as PLANNING, WORKING, EVIDENCE, REVIEWING, DONE, ERROR, and NEEDS_HUMAN. Allow each phase to accept only valid next steps.

Step 5. Let tests decide

The worker may say that something works, but the orchestrator must run the tests itself. Think unit tests, type checking, builds, and browser E2E tests for UIs.

Step 6. Build recovery before the first long overnight run

Heartbeat, stale detection, watchdogs, retries, caps, and an audit log are essential. They prevent one timeout from stopping the entire autonomous run.

Start small: one challenge

Choose a task that can demonstrably succeed or fail within a few hours. Before starting, write five to ten concrete acceptance criteria. Then let the orchestrator build autonomously until the tests pass or a genuine human decision is required.

A good first experiment: “Build a browser app that does X, write the tests before implementation, work on a separate Git branch, commit only after independent review, and return NEEDS_HUMAN when a product decision is required.”
