From idea to execution

The human prompt was really only the beginning

The main human input was the idea for the demonstrator. AI then helped choose the five challenges, expanded them into full challenge descriptions and produced the more detailed prompts the orchestrator could execute. Those longer prompts were themselves largely AI-generated.

What was actually used

The original master prompt

The generic launch prompt was 27 lines long. It worked well, but safety, Git, testing, fallback behaviour and the Lovable policy can largely live as stable system rules inside the orchestrator.

Show the full original prompt
Read the challenge folder and all supplied public/synthetic context. Build the best complete working solution autonomously using the normal orchestrator flow for planning, implementation, testing, review and polish.

Rules:
- Do not request human intervention for non-essential choices.
- Use only public or synthetic data and documentation.
- Do not use patient data, confidential information or internal source code.
- Do not use sudo/root. User-level dependencies are allowed.
- If a dependency or tool is unavailable, choose a safe alternative and continue.
- Build a polished browser application with clear visual output.
- Test the core functionality end-to-end and fix defects where possible.
- Keep a reproducible source tree, test evidence and a short final report.
- Do not modify unrelated repositories, systems or production environments.

Resource strategy:
- Treat Lovable as a scarce premium resource, not as the default implementation environment.
- Do planning, research, architecture, core logic, coding, debugging, testing, code review and most refinement with the normal orchestrator/model stack and local tools first.
- Use Lovable only for high-leverage frontend work where it is likely to materially improve visual quality, interaction design or final polish.
- Before each Lovable call, ask whether the same improvement can be achieved reliably with local code or the normal model/tool stack. If yes, prefer that route.
- Prefer one well-prepared Lovable pass over many small exploratory Lovable iterations. Batch related UI changes into a single clear request when practical.
- Do not spend Lovable credits on backend logic, algorithm design, data processing, tests, documentation or routine bug fixing unless there is a compelling reason.
- After a Lovable pass, continue refinement, debugging and testing outside Lovable whenever possible.
- Never lower the final quality bar merely to save Lovable credits. Spend credits when they are genuinely needed to make the demo polished and presentation-ready.
- Stop using Lovable once the application is visually coherent, polished and demo-ready. Further cosmetic iteration is not a goal by itself.

Success means: a working demo, objective evidence that the core algorithm works, and a clear account of any remaining limitations.

Execute the selected challenge fully autonomously. Read all supplied context and acceptance criteria, plan the work in small testable steps, build a polished browser demo, test the core functionality end-to-end, have the result independently reviewed and repair defects where needed. The human base prompt

This is how short the real start can be

I want to show my colleagues what AI can already do beyond prompt-in/prompt-out. Help me choose five different small software challenges that form a good stress test for my autonomous AI environment. Then turn them into full assignments and acceptance criteria and have the orchestrator build, test, review and repair them autonomously. The final result should be five demonstrably working browser demos.

This is the layer closest to the original human thought. The longer technical prompts can then be generated by AI and by the environment's fixed rules.

After choosing the five ideas

The launch prompt can become even shorter

Work through these five software challenges fully autonomously. Create the final challenge briefs and acceptance criteria yourself, build and test each solution, have the result independently reviewed, repair defects and deliver five demonstrably working browser demos.
The interesting part: the real human input can look much more like an ordinary goal description. The technical detail can be generated by the environment and by an intermediate AI step.
