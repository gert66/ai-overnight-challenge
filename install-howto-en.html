Technical help for beginners

From your laptop to a server ChatGPT can finish itself

This page tells you exactly where to type each command and what it does. You handle only the few steps needed to connect Remote Desktop Commander. After that, ChatGPT takes over the technical setup.

First: PowerShell, SSH and SSH keys

PowerShellA command window on your own Windows computer.
SSHA secure connection from your computer to the Linux server at Hetzner.
SSH keyA digital key pair. The public key goes to Hetzner. The private key stays on your computer and is never shared.
Important: before SSH, commands run on your own computer. Once your prompt looks like root@your-server:~#, commands run on the Hetzner server.

1. Create an SSH key on your own computer

Windows

Press the Windows key, type PowerShell, and open PowerShell or Terminal. Your prompt looks roughly like PS C:\Users\yourname>.

WHERE: your own Windows computer, in PowerShell
ssh-keygen -t ed25519 -C "ai-challenge"

Press Enter for the default file location. If the file already exists, answer n and keep the existing key. For the simplest setup, you may leave the passphrase empty by pressing Enter twice.

Show the public key:

WHERE: still in PowerShell on your computer
Get-Content "$env:USERPROFILE\.ssh\id_ed25519.pub"

Copy the entire line beginning with ssh-ed25519.

macOS / Linux

WHERE: Terminal on your own computer
ssh-keygen -t ed25519 -C "ai-challenge"
cat ~/.ssh/id_ed25519.pub
Never share: the file without .pub, for example id_ed25519, is your private key.

2. Create the Hetzner server

Open Hetzner Cloud Console ↗

  1. Choose Ubuntu 24.04 LTS as the image.
  2. Choose x86 architecture, not ARM.
  3. Use at least about 2 vCPU / 4 GB RAM / 40 GB disk. About 4 vCPU / 8 GB RAM / 80 GB disk is recommended.
  4. Make sure the server receives a public IPv4 address.
  5. Under SSH Keys, choose Add SSH Key, paste the entire public key line from step 1, give it a name such as my-laptop, and select it for this server.
  6. Create the server and copy its real Public IPv4, for example 203.0.113.42.
The IP 203.0.113.42 is only an example. Always use the real Public IPv4 shown for your own server.

3. Make the first SSH connection

Return to PowerShell on Windows or Terminal on macOS/Linux.

WHERE: your own computer, not the server yet
ssh root@203.0.113.42

Replace 203.0.113.42 with your real Public IPv4 address. Do not type brackets around the IP.

The first time, SSH may ask Are you sure you want to continue connecting?. Type yes and press Enter.

Success? Your prompt now looks roughly like root@your-server:~#. From here onward, commands run on the Hetzner server.

4. Download and run the small bootstrap

WHERE: on the Hetzner server, in your SSH session as root

Download it first as a readable file:

curl -fsSL https://raw.githubusercontent.com/gert66/ai-overnight-challenge/main/setup/bootstrap.sh -o /tmp/ai-challenge-bootstrap.sh

You can inspect it with:

less /tmp/ai-challenge-bootstrap.sh

Then run it:

bash /tmp/ai-challenge-bootstrap.sh

A successful run ends with AI CHALLENGE BOOTSTRAP READY.

The bootstrap contains no passwords, API keys or tokens. It also does not install the full orchestrator yet.

5. Start Remote Desktop Commander

WHERE: on the Hetzner server, in the same SSH session
ai-challenge-remote

Complete the browser pairing. The remote agent then runs in a tmux session, so your SSH window does not have to remain open.

Check status:

ai-challenge-remote status

Latest logs:

ai-challenge-remote logs

Official Remote Desktop Commander guide ↗

Acceptance test: make ChatGPT execute a real command. Seeing only “online” is insufficient.

6. Handoff to ChatGPT

WHERE: as a message in ChatGPT, not in PowerShell or SSH
I have completed the AI Challenge bootstrap. Connect to my server through Desktop Commander. First prove the connection by running hostname and whoami. Then read ~/AI_CHALLENGE_CONTEXT.md, ~/AI_CHALLENGE_STATUS.json and ~/AI_CHALLENGE_MANIFEST.json. Inspect the real machine state and continue the installation from the first incomplete step. Do as much as possible yourself. Ask me only when you need an authorization, password, browser login, payment action, secret, or another action I must personally approve. Do not send me back to SSH for routine technical work that you can perform yourself.

ChatGPT should inspect the real machine first and only then continue installation.

Recovery

SSH session lost

Reconnect with ssh root@SERVER_IP. The bootstrap is idempotent and can be run again.

Remote Desktop Commander offline

ai-challenge-remote status
ai-challenge-remote

SSH always remains your emergency access.

Stopped halfway

Start a new ChatGPT chat with the same handoff instruction. ChatGPT reads the status, inspects the real machine and continues from the first incomplete step.

After reboot

The orchestrator, health timer and watchdog must return automatically. Remote Desktop Commander must then be tested again with a real command. If the current Remote version needs fresh browser authorization, only that authorization is a human step.

Authentication failed

Let ChatGPT restart the login flow. Enter passwords, 2FA and secrets yourself. Never put them in Git or the bootstrap.
