What do you need?

For a first personal setup, this is enough.

  • A GitHub account (repositories, commits, audit trail)
  • A small Linux cloud VM, for example at Hetzner Cloud (around 2 vCPU / 4 GB RAM)
  • An AI account, for example ChatGPT or Claude, plus a coding agent on the VM (in this guide: Claude Code)
  • An SSH key on your own computer
  • Basic software on the VM: Git, Python, Node/npm
  • Optional: Desktop Commander, for direct, bounded VM access via ChatGPT

What does it roughly cost?

The fixed costs are modest. You don't need a GPU server or a large cloud platform. Check current prices with the provider before ordering.

The route, step by step

Twelve steps, the same order as the original beginner guide. Each step links to the full command-by-command recipe.

  1. 1

    Create the three accounts

    GitHub (for code and audit trail), Hetzner Cloud (for the VM) and an AI account. For the coding agent on the VM, the original guide uses Claude Code; for the human chat layer you can use ChatGPT or Claude.

    Full explanation →

  2. 2

    Create an SSH key on your own computer

    SSH is the secure connection between your laptop and the Linux VM. Never share your private key, only the public .pub file.

    Full explanation →

  3. 3

    Create the VM

    A small Ubuntu server with around 2 vCPU and 4 GB RAM is enough, for roughly €6–7 per month as an order of magnitude.

    Full explanation →

  4. 4

    Connect to the VM and create a regular admin

    Log in as root the first time, then create a regular admin account and use that for day-to-day work.

    Full explanation →

  5. 5

    Install the basic software

    Git, Python, and Node/npm (via nvm) are the minimal development environment.

    Full explanation →

  6. 6

    Connect the VM to GitHub

    A dedicated SSH key for the VM, setting your Git identity and cloning your first repository.

    Full explanation →

  7. 7

    Install and activate the coding agent

    Start interactively and let the agent do one simple task first. Optional: Desktop Commander as a tool bridge, separate from the autonomous state machine.

    Coding agent → · Desktop Commander (optional) →

  8. 8

    Set environment variables and secrets securely

    Tokens and API keys never belong directly in code or Git. Use a local .env file with strict permissions, kept out of Git.

    Full explanation →

  9. 9

    Do one manual end-to-end test first

    Prove that the agent, Git and tests work before you automate: write a small test, have it committed and pushed to a separate branch.

    Full explanation →

  10. 10

    Then add the orchestrator

    A first version only needs to do six things: PLAN (one concrete build step with acceptance criteria), BUILD (let the coding agent work), TEST (run fixed test commands), REVIEW (a separate, independent check), COMMIT (only after a green light) and REPEAT.

    Full explanation → · The full architecture →

  11. 11

    Add monitoring and a watchdog

    Have active jobs periodically write a heartbeat and let a separate watchdog step in if a job demonstrably stalls. Always give retries a maximum.

    Full explanation →

  12. 12

    Final check, then your first run — and assess the next morning

    Go through the final checklist items (SSH, GitHub, agent, secrets, tests, state, retries, Git, watchdog). Then pick a task that can demonstrably succeed or fail within a few hours, write a few concrete acceptance criteria in advance, and let the orchestrator build autonomously until the tests are green or a genuine human decision is needed. The next morning, assess the result: does the demo work, is there test evidence, and can the commits be followed logically?

    Full final check →

Note: never put API keys or tokens directly in code or Git. Use a local .env file with strict permissions and keep it out of Git.
A good first trial: “Build a browser app that does X, write the tests before the implementation, work on a separate Git branch, commit only after independent review, and return NEEDS_HUMAN if a product decision is needed.”
