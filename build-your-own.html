Wat heb ik nodig, wat kost het en hoe bouw ik mijn eigen AI-softwarefabriek?

Je hoeft niet te beginnen met een groot cluster. Deze challenge draaide op een kleine VM met 2 vCPU en 3,7 GiB RAM. De kern is een Linux-machine, Git, een agent die code kan schrijven, een orchestrator die het proces bewaakt en tests die bepalen wanneer iets echt klaar is.

2. Praktische persoonlijke setup

VM + AI
Voeg planner/reviewer, logging, watchdog en model-fallback toe. Dit lijkt het meest op de challenge-opstelling.

3. Zwaardere productie-opzet

usage based
Meer parallelle jobs, strengere approvals, secrets management, CI/CD en monitoring. De kosten hangen dan vooral af van modelkeuze en gebruik.

Wat hoeft niet?

Geen GPU, geen Kubernetes en geen dure server om te starten. Voor browserapps en normale softwaretaken is CPU-compute vaak genoeg.

Wat kostte deze stresstest?

Er zijn twee verschillende getallen die je uit elkaar moet houden: de werkelijk gelogde worker-kosten per challenge en de bredere modeltelemetrie inclusief extra review- en contextverkeer.

Stap 1. Neem een kleine VM

Begin met ongeveer 2 vCPU, 4 GB RAM en 40 GB disk. Installeer Python, Node/npm en Git. Voeg pas capaciteit toe wanneer je echte bottlenecks meet.

Stap 2. Maak Git leidend

Elke job werkt op een eigen branch. Laat de orchestrator controleren dat de tree schoon is, de branch actueel is en goedgekeurde batches afzonderlijk worden gecommit.

Stap 3. Koppel minimaal één coding agent

Claude Code is geschikt als worker/reviewer. Gemini kan als goedkopere primary of voor lichtere taken worden ingezet. Houd de provider achter een abstractielaag zodat je kunt wisselen.

Stap 4. Bouw een echte state machine

Gebruik expliciete fasen zoals PLANNING, WORKING, EVIDENCE, REVIEWING, DONE, ERROR en NEEDS_HUMAN. Laat elke fase alleen geldige vervolgstappen accepteren.

Stap 5. Laat tests beslissen

De worker mag zeggen dat iets werkt, maar de orchestrator moet zelf tests uitvoeren. Denk aan unit tests, typecheck, build en browser-E2E voor UI's.

Stap 6. Bouw recovery vóór de eerste lange nacht

Heartbeat, stale-detectie, watchdog, retries, caps en een auditlog zijn geen luxe. Ze voorkomen dat één timeout de hele autonome run stillegt.

Wat ik anders zou doen dan vannacht

Modelrouting vooraf testen

Test API-key, service account en fallback vóór de lange run. De Google-authenticatiefout maakte de nacht onnodig duurder.

Pushen als aparte eindgate

Een job is pas echt klaar wanneer de geaccepteerde commits ook remote staan. Maak local ahead = 0 onderdeel van DONE.

Diskruimte bewaken

Node modules, Playwright browsers, builds en screenshots groeien snel. Zet vroegtijdig een disk-threshold en cleanup-policy aan.

Goedkoop model voor routine

Laat de dure modellen focussen op ontwerp, lastige bugs en onafhankelijke review. Dat kan de variabele kosten sterk drukken.

Begin klein: één challenge

Kies een taak die in een paar uur aantoonbaar kan slagen of falen. Schrijf vóór de start vijf tot tien concrete acceptance criteria. Laat daarna de orchestrator autonoom bouwen totdat de tests groen zijn of een echte menselijke beslissing nodig is.

Een goede eerste proef: “Bouw een browserapp die X doet, schrijf de tests vóór de implementatie, werk op een aparte Git-branch, commit alleen na onafhankelijke review en geef NEEDS_HUMAN terug als een productbeslissing nodig is.”
